# RK3588 model checks

`compile_rknn.py` compiles the dense XFeat float32 ONNX export for RK3588.
It does not quantize weights to integers. The compiler selects float16 operations.
The input must already have the normalization used by the Rust dense adapter.
Do not apply image normalization a second time in RKNN Runtime.

The tool requires RKNN Toolkit2. The container supplies the tested compiler.
Python runs only during asset creation and simulator checks. A deployed adapter
must use RKNN Runtime. No deployed RKNN adapter is included in this package.

From the repository root, build the compiler image:

```sh
docker build -f tools/visual-inference/rknn.Dockerfile \
  -t navigate-rknn-compiler tools/visual-inference
```

Mount the model directory, one input directory, and an output parent directory.
Use absolute host paths in each mount. The input is little-endian float32 with
shape 1 by 1 by 576 by 800. The output directory must not exist.

```sh
docker run --rm --network none --cpus 4 --memory 4g \
  -v "$PWD/tools/visual-inference:/tool:ro" \
  -v /absolute/models:/models:ro \
  -v /absolute/inputs:/inputs:ro \
  -v /absolute/results:/results \
  navigate-rknn-compiler python /tool/compile_rknn.py \
  /models/xfeat-dense-f32.onnx /results/new-rk3588-check \
  --validate-input /inputs/input.f32
```

The simulator compares all three outputs with ONNX Runtime CPU execution.
It rejects missing outputs, wrong shapes, non-finite values, and excessive tensor
error. The default absolute error limit is 0.2. This numerical limit is not a
pose-acceptance policy. Run selected-match and pose tests on the target board.
The report records the source, artifact, and input SHA-256 digests.
Compiler output can have different digests across builds.

Run the simulator comparison guardrails in the same image:

```sh
docker run --rm --network none \
  -v "$PWD/tools/visual-inference:/tool:ro" \
  -w /tool navigate-rknn-compiler python -m unittest test_rknn_compile
```

The measured artifact compiled with Toolkit2 2.3.2 on Linux ARM64. It used
2,138,010 bytes. The simulator produced finite outputs on one real input.
The maximum absolute differences were 0.01509 for descriptors, 0.07387 for
keypoint logits, and 0.001577 for reliability. No physical RK3588 was used.
This check does not measure latency, power, quantization quality, or pose accuracy.

Use the board's supported RKNN Runtime and NPU driver. Check the model input and
output attributes at load time. Preserve float32 host preprocessing and descriptor
sampling. Keep device handles and tensors inside the matcher adapter. Return
Navigate pixel correspondences to the shared geometric verifier.

[RKNN Toolkit2 and Runtime](https://github.com/airockchip/rknn-toolkit2) supplies
the compiler, simulator, and board runtime interfaces.
